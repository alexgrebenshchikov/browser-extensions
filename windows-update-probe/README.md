# Windows Update Probe

Автономное Manifest V3 расширение для проверки
`chrome.windows.update(windowId, {focused: true})` в Яндекс Браузере на Android.
Команда поступает из окна расширения. Проверяемый вызов выполняется в фоновом обработчике `chrome.alarms`.
Сервер, Node.js, npm и ADB для выполнения сценария не требуются.

## Установка

1. Скачать [windows-update-probe.zip](https://github.com/ymbrocore/browser-extensions/raw/refs/heads/master/windows-update-probe.zip).
2. Распаковать архив в отдельную папку на устройстве. В ней должны находиться `manifest.json`, `background.js`,
   `popup.html` и `popup.js`.
3. В отдельном тестовом профиле Яндекс Браузера открыть `browser://extensions` и включить **Режим разработчика**.
4. Нажать **Загрузить распакованное расширение**. В файловом диалоге Android открыть папку с `manifest.json`,
   нажать **Использовать эту папку**, затем **Разрешить**.
5. Открыть **Меню вкладки** (три точки в строке адреса), прокрутить меню вниз, выбрать **Расширения**, затем
   **Windows Update Probe**.

## Проверка

Перед началом сохранить нужные вкладки: сценарий `empty` требует закрыть все вкладки тестового профиля.
Во время отложенного запуска оставить Браузер открытым на экране. Не перезапускать приложение и не перезагружать
расширение.

### normal — контроль с открытой вкладкой

1. Открыть обычную веб-страницу.
2. В окне расширения нажать **Запустить normal**. Дождаться сообщения `normal: запуск через … с`.
3. Закрыть окно расширения и оставить веб-вкладку открытой.
4. Через 60 секунд открыть расширение и прочитать последний запуск в журнале.

Ожидается `label: "normal"`, `phase: "after"`. В `before.windows` есть выбранное окно с непустым `tabs`.
`after.id` совпадает с `before.windowId`, `after.error` равен `null`. Браузер остаётся открыт.

### empty — существующее окно без вкладок

1. Нажать **Запустить empty**. Дождаться сообщения `empty: запуск через … с`.
2. Закрыть окно расширения. До истечения 30 секунд закрыть все вкладки штатным интерфейсом, включая страницу
   расширений. Оставить Браузер открытым на главном экране без вкладок.
3. Через 60 секунд после запуска открыть `browser://extensions`. Открыть **Меню вкладки** → **Расширения** →
   **Windows Update Probe** и прочитать последний запуск в журнале. На главном экране без вкладок этот пункт меню
   недоступен, поэтому страница для чтения журнала открывается после ожидания.
4. Закрыть окно расширения и открыть меню приложения.

Ожидается `label: "empty"`, `phase: "after"`. В `before.windows` существует окно с ID `before.windowId` и
`tabs: []`; вкладок нет ни в одном из перечисленных окон. `after` содержит callback: тот же ID окна и
`error: null` либо текст штатной ошибки API. Браузер не завершился; меню открывается и отвечает на нажатия.

Отсутствие `after`, статусы `armed`, `before`, `invalid`, `no-window`, `cancelled`, `error`, а также неверное число
вкладок не подтверждают прохождение. Оценивать число вкладок по сохранённому `before`, а не по состоянию после
открытия страницы для чтения. Задержка `chrome.alarms` может превышать 30 секунд: если вызов не успел выполниться
до открытия страницы для чтения, такой запуск не подтверждает сценарий пустого окна.

## Журнал и повторный запуск

- Перед вызовом API расширение дожидается сохранения `before` в `chrome.storage.local`.
- При callback оно сохраняет `after` и считывает `chrome.runtime.lastError` внутри callback.
- Журнал содержит последние 20 запусков, ID окон и вкладок. Адреса и содержимое страниц не собираются.
- **Сохранить JSON** выгружает журнал через обычную загрузку Браузера.
- **Отменить запуск** снимает отложенное задание. **Очистить журнал** доступна после завершения или отмены.
- Если Браузер упал, сначала сохранить журнал после перезапуска. Отсутствие `after` само по себе не устанавливает
  причину сбоя. Затем отменить оставшееся задание и запустить сценарий заново.
- Расширение не отправляет журнал по сети. Для работы используются только разрешения `alarms` и `storage`.
- После проверки удалить тестовое расширение через страницу расширений.

## Исходники

Готовые файлы выполняются без сборки. Архив содержит те же исходники, что папка `windows-update-probe` в репозитории.
Это отдельная проверка; основной Browser API Test не запускается и не меняется.

## Проверка на Android

4 ноября 2026 года сценарии выполнены на физическом Pixel 9, Android 14, Яндекс Браузер 26.11.0.210.
В `normal` получен callback с ID существующего окна и `error: null`. В `empty` до вызова сохранено существующее
окно с `tabs: []`, затем получен callback с тем же ID окна и `error: null`; приложение осталось открытым.
Использовалась установленная на устройстве сборка. Планшет и другие версии Браузера в этом прогоне не проверялись.

# Проверка загрузок без Node.js и Python

[Открыть тестовую страницу](https://ymbrocore.github.io/testpages/download-checks.html).
Страница создаёт непустой Blob и проверяет сохранённые файлы через File API. Содержимое выбранного файла
не отправляется на сервер. Console и ADB для подготовки не нужны.

## Непустой Blob

Для этого сценария компьютер не нужен.

1. На устройстве открыть тестовую страницу.
2. Нажать **Скачать «Проверка Blob.txt»** и подтвердить сохранение.
3. Открыть загрузки Браузера. Проверить завершённый файл с кириллическим именем и размером 31 Б.
4. Вернуться на страницу. Нажать **Выбрать сохранённый файл из загрузок** и выбрать сохранённый файл.

Ожидается **Совпадает с эталоном** и следующий результат:

```json
{"name":"Проверка Blob.txt","size":31,"content":"Blob download check\n1234567890\n","matches":true}
```

## Подготовка Charles для паузы и продолжения

1. Сохранить исходные режим, адрес и порт прокси устройства. Запустить Charles на компьютере. Подключить компьютер и Android-устройство к одной сети Wi-Fi.
2. В Charles открыть **Proxy → Proxy Settings** и прочитать порт HTTP-прокси. В **Help → Local IP Address**
   прочитать IP-адрес компьютера.
3. В настройках подключённой сети Wi-Fi на Android выбрать ручной прокси. Ввести IP-адрес компьютера и порт
   Charles из предыдущего пункта. Разрешить подключение этого устройства в Charles.
4. В Charles открыть **Proxy → Throttle Settings**. Ограничить скорость скачивания до **128 Кбит/с (16 КБ/с)**.
   Применить ограничение к **ymbrocore.github.io:443**. Включить **Throttling** до начала скачивания и оставить
   включённым до его завершения. Не подменять тело ответа.
5. В загрузках Браузера удалить только старый тестовый файл **risk5-pause-resume.webm**, оставшийся от предыдущего
   прогона. Новая загрузка должна получить это имя без добавленного номера.

При открытии страницы на устройстве в Charles должно появиться соединение с ymbrocore.github.io:443.
Страница должна открываться без ошибок сертификата. Расшифровка HTTPS не является критерием этого кейса:
содержимое и SHA-256 проверяются на самой странице.

## Пауза и продолжение

1. На устройстве открыть тестовую страницу. Нажать **Скачать risk5-pause-resume.webm** и подтвердить скачивание.
   В Android-шторке должен постепенно расти объём незавершённой загрузки.
2. Когда получено от **0,5 до 1 МБ из 3,67 МБ**, нажать **Остановить** в уведомлении этой загрузки.
3. Проверить **Продолжить** вместо **Остановить**. Дважды проверить неизменный числовой объём с интервалом
   около 5 секунд. Сразу нажать **Продолжить**.
4. Проверить рост объёма у той же незавершённой загрузки и отсутствие второй активной загрузки этого файла.
   Дождаться завершения.
5. Открыть загрузки Браузера. Должен быть один завершённый **risk5-pause-resume.webm** без ошибки.
6. Вернуться на страницу. Через **Выбрать сохранённый файл из загрузок** выбрать этот файл в системном пикере.

Ожидается **Совпадает с эталоном** и следующий результат:

```json
{"name":"risk5-pause-resume.webm","size":3667214,"sha256":"4c3d89f4130a6349bab2a6b9c57066879c95c87f966ca5ff4b8c689e4834184b","matches":true}
```

Каждое нажатие ссылки формирует новый URL файла, чтобы повторное скачивание не использовало браузерный кеш.
Если файл загрузился сразу, медленная передача для кейса не подготовлена: проверить прохождение трафика
через Charles и применение Throttling, затем начать заново. Мгновенное завершение не подтверждает паузу.

После проверки выключить Throttling и восстановить сохранённые режим, адрес и порт прокси сети Wi-Fi на устройстве.

сохранены для прежнего локального стенда и в текущую подготовку не входят.

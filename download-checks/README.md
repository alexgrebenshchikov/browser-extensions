# Проверка загрузок без Node.js

Готовые данные для двух сценариев Яндекс Браузера на Android:

- непустой Blob с кириллическим именем и точным содержимым;
- сохранение всех байтов после паузы и продолжения медленной HTTP-загрузки.

## Подготовка локального стенда для медленной загрузки

Для медленной HTTP-загрузки на компьютере нужны Python 3 и ADB. Сторонние Python-пакеты и Node.js не используются.
Предоставленный архив `download-checks.zip` содержит страницу, JavaScript, сервер и эталонный файл.

1. Распаковать архив. В терминале этой папки выполнить `python3 server.py`.
2. В другом терминале выполнить `adb -s <serial> reverse tcp:8769 tcp:8769`, заменив `<serial>` идентификатором
   тестируемого устройства. Сервер оставить работающим до завершения сценариев.

## Непустой Blob

Для этого сценария компьютер, Python, ADB и Node.js не нужны. Страница работает через GitHub Pages.

1. На устройстве открыть [страницу проверки загрузок](https://ymbrocore.github.io/testpages/download-checks.html).
2. Нажать **Скачать «Проверка Blob.txt»** и подтвердить сохранение.
3. Открыть загрузки Браузера. Проверить завершённый файл с кириллическим именем и ненулевым размером.
4. Вернуться на тестовую страницу. Нажать **Выбрать сохранённый файл из загрузок** и выбрать файл.

Ожидается **Совпадает с эталоном**. В данных файла должны быть:

```json
{"name":"Проверка Blob.txt","size":31,"content":"Blob download check\n1234567890\n","matches":true}
```

Содержимое читается через File API на устройстве. Оно не отправляется на сервер. Console не требуется.

## Пауза и продолжение

1. На устройстве открыть `http://localhost:8769/` и нажать **Начать медленную загрузку**. Подтвердить скачивание.
2. В начале передачи, после первых наблюдений роста объёма, открыть Android-шторку и нажать **Остановить** в уведомлении загрузки.
3. Проверить переход в паузу. Дважды проверить неизменный объём с интервалом около 5 секунд, затем сразу нажать **Продолжить**.
4. Проверить рост объёма у той же загрузки и отсутствие второй загрузки файла. Дождаться завершения.
5. Открыть загрузки Браузера. Должен быть один завершённый файл `risk5-pause-resume.webm`.
6. На странице стенда выбрать сохранённый файл через **Выбрать сохранённый файл из загрузок**.

Ожидается **Совпадает с эталоном** и следующие поля:

```json
{"name":"risk5-pause-resume.webm","size":3667214,"sha256":"4c3d89f4130a6349bab2a6b9c57066879c95c87f966ca5ff4b8c689e4834184b","matches":true}
```

Перед повторным прогоном удалить только оставшиеся тестовые файлы с этими именами, чтобы Браузер не добавил номер
к имени нового файла. После проверки остановить сервер сочетанием Ctrl+C и выполнить
`adb -s <serial> reverse --remove tcp:8769`.

## Свойства стенда

Сервер слушает только `127.0.0.1:8769`. Файл передаётся порциями по 8192 байта каждые 250 мс; полная передача занимает
около двух минут на одном соединении; параллельные запросы сокращают общее время. Долгая пауза перед
возобновлением может скрыть промежуточный рост счётчика. Поддерживаются `Range`, `If-Range`, `Content-Range`, `ETag`, ответы 200, 206 и 416.
Размер и SHA256 эталона проверяются при запуске; с другим содержимым сервер не запустится.
Журнал доступен по `/status` и сохраняется в `server-events.jsonl` рядом с сервером.

Эталонное видео взято из [ymbrocore/testpages](https://github.com/ymbrocore/testpages). Первоначальный файл:
[video.webm](https://ymbrocore.github.io/testpages/video.webm). Его размер и SHA256 указаны выше.

## Страница и исходники

[Статическая страница](https://ymbrocore.github.io/testpages/download-checks.html) предоставляет загрузку Blob
и проверку сохранённых файлов. В локальном варианте та же страница доступна по адресу `http://localhost:8769/`.
Медленная отдача и HTTP Range работают через Python-сервер; на статической странице соответствующие элементы скрыты.

[Пакет и исходники](https://github.com/ymbrocore/browser-extensions/tree/master/download-checks).
Архив `download-checks.zip` в корне репозитория содержит те же пять файлов, что папка `download-checks`.
